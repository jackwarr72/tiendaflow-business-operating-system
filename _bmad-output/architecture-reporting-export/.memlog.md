- (direction) altitude=feature; scope=reporting & data-export capability (charts/tables of sales, inventory, messages + report generation + PDF/CSV export)
- (decision) AD-1 Reporting module location: new src/app/reporting/ (route group) with server actions + page. Binds: all reporting UI, export routes, dashboard. Prevents: ad-hoc report queries scattered across pages and duplicated aggregation logic. Rule: every report metric is computed by a server action in src/app/reporting/actions.ts and consumed by a route-group page; components never query db directly.
- (decision) AD-2 Export is server-side Route Handler only. Binds: CSV and PDF export endpoints. Prevents: client-side export leaking db credentials / building blobs in browser. Rule: export endpoints are Route Handlers under src/app/api/report/ that stream the result as an HTTP Response with Content-Disposition attachment; CSV built by streaming rows, PDF built by rendering HTML server-side.
- (decision) AD-3 Report data contract: a report is {title, generatedAt, period, rows, summary}. Binds: every report output (charts, tables, CSV, PDF). Prevents: inconsistent column sets / date formats / currency formatting across exports. Rule: report shape is defined in src/app/reporting/types.ts; CSV and PDF consumers both consume the same Report object, never re-derive columns from raw rows.
- (decision) AD-4 Money formatting is centralized. Binds: all currency display and export. Prevents: MXN vs USD mixups and locale drift between UI and CSV/PDF. Rule: a single src/lib/money.ts helper formats every numeric amount as MXN with 2 decimals; exports use the same helper so PDF and CSV match the screen.
- (decision) AD-5 Inventory report uses materialized low-stock threshold. Binds: inventory report and stock alert. Prevents: O(n) full-table scan on every dashboard load. Rule: low-stock alert threshold lives in src/app/reporting/config.ts (default 5) and is applied in the same predicate used by getDashboardStats so dashboard and report never disagree.
- (decision) AD-6 Messages-to-send report derives from customer preferredChannel and order channel, not a separate message table. Binds: messaging report. Prevents: inventing a message store that duplicates order channel data. Rule: the 'messages to send' report is a view over orders/customers grouped by channel with status filter; no new messaging entity is created for reporting.
- (assumption) ASSUMPTION: PDF export uses server-rendered HTML-to-PDF via a lightweight approach (Next Route Handler returns HTML, browser prints) rather than a headless browser lib, because no PDF/HTML-to-PDF dependency exists in package.json and adding puppeteer is heavy. Upgrade path: add puppeteer/playwright if PDF fidelity becomes a requirement.
- (assumption) ASSUMPTION: CSV uses plain text with a header row, UTF-8, semicolon or comma per locale. No csv/json npm package added - stdlib string join suffices for the row counts expected.
- (decision) AD-7 Report data model: each report is a typed object {kind, title, generatedAt, period, rows, summary} defined in src/app/reporting/types.ts. Binds: all report consumers (charts, tables, CSV, PDF). Prevents: per-report ad-hoc row shapes. Rule: a report's rows are always an array of plain objects with string keys; summary is a record of scalar aggregates; the CSV/PDF exporters consume the same Report object.
- (decision) AD-8 Report set: four report kinds are owned by this module - sales (by day / by channel / by product), inventory (stock on hand, low-stock list, sold-out list), messages-to-send (customers by preferred channel with pending orders), and expenses (by category, totals). Binds: reporting page, export endpoints. Prevents: an unbounded list of bespoke report types. Rule: new report kinds are added as a kind enum value + a query in src/app/reporting/actions.ts + a row in the report set table; no report exists outside this set.
- (decision) AD-9 Report generation entry point: a single server action generateReport(kind, period) in src/app/reporting/actions.ts returns a typed Report. Binds: every report consumer including the page and both exporters. Prevents: each chart/table re-implementing its own SQL. Rule: the page calls generateReport once per kind; the CSV/PDF exporters call the same action and only differ in serialization.
- (decision) AD-10 CSV export: Route Handler src/app/api/report/[kind]/route.ts streams a text/csv Response with header row, UTF-8, Content-Disposition attachment named <kind>-<period>.csv, using the money helper for amounts. Binds: all CSV output. Prevents: inconsistent quoting/escaping per report. Rule: CSV is header + one row per report row, values quoted only when they contain comma/quote/newline; numbers never formatted as locale strings.
- (decision) AD-11 PDF export: Route Handler src/app/api/report/[kind]/pdf/route.ts renders the Report to HTML server-side and returns it as text/html with Content-Disposition attachment; the user prints to PDF from the browser. Binds: all PDF output. Prevents: adding puppeteer/playwright for a fidelity requirement that does not exist yet. Rule: PDF HTML reuses the same Report object and money helper as CSV, so numbers match; no headless browser dependency in package.json.
